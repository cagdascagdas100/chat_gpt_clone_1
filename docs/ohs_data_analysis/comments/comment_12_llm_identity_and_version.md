# Comment 12 — LLM name and version

## Reviewer comment
`Adı ve versiyonunun da yazılması gerekir.`

## Selected manuscript wording
`large language models (LLMs)`

The selected phrase occurs in the Methods section where the manuscript states that accident scenarios were generated by an LLM and then refined by the authors.

## Final editorial decision
Do not add an LLM name or version unless the study has an auditable implementation record identifying the exact model used. The currently available analytical artifacts document the machine-learning risk models but do not document an LLM provider, model identifier, dated version or snapshot, access route, prompt protocol, decoding settings, or generation logs. Adding a model name now would therefore be speculative.

This comment must be resolved together with Comment 1. Comment 1 already requires removal of the LLM claim from the Abstract. The most internally consistent and methodologically defensible revision is to remove manuscript-facing claims that the proposed framework generated scenarios with an LLM, rather than inventing a model name and version that cannot be verified.

Literature-review sentences describing LLM use in other studies may remain. The removal applies only to claims about the implementation of the proposed framework.

## Preferred section-title revisions
- `3.2 Generation & evaluation of potential risk scenarios` → `3.2 Structured risk-scenario definition and evaluation`
- `3.2.1 Integration of large language models` → `3.2.1 Structured definition of equipment-related accident scenarios`
- Retain a separate subsection for numerical risk-scenario evaluation if needed.

## Preferred replacement paragraph for Section 3.2
`The framework evaluates structured accident scenarios associated with each equipment–malfunction pair using machine-learning-derived risk coefficients. Each scenario is represented by a standardized set of attributes, including the event sequence, accident mechanism, body region, injury type, injury severity, and likelihood. Except for injury type and body region, scenario-level risk values are calculated directly from the corresponding coefficients. Injury-type and body-region coefficients are then mapped to each scenario. For each equipment–malfunction pair, the three scenarios with the highest calculated risk values are presented in the application together with their associated injury locations (Figure 2).`

This wording describes the verifiable scoring and presentation logic without claiming an unverified generative mechanism.

## Preferred replacement paragraph for the scenario-library description
`The scenario library is organized hierarchically by work area, work zone, equipment, and equipment malfunction. For each equipment–malfunction pair, scenario records follow a standardized template comprising the event sequence, accident mechanism, body region, injury type, injury severity, and likelihood. This common representation enables the scenarios to be evaluated systematically using the machine-learning-derived risk coefficients.`

The exact provenance of the scenario records—expert-authored, rule-based, or generated previously and then curated—must be confirmed from project records before a stronger authorship statement is made. Until that provenance is verified, the manuscript should use neutral language such as `structured scenario library` and should not state that scenarios were generated by an LLM.

## Red-highlight treatment for the final workbook
Because the methodological claim changes substantially, the full replacement paragraph should be shown in the final workbook. The newly inserted wording that replaces the LLM claim should be red within the complete revised paragraph.

## Minimum reporting requirements only if LLM use is later verified
If an auditable record is found before submission, the Methods section should report at minimum:
- provider and exact model identifier;
- version, dated snapshot, or release designation;
- access route, such as API or web interface;
- date or date range of access;
- system and user prompt structure;
- temperature, top-p, maximum-output, and seed settings when applicable;
- number of generations per equipment–malfunction pair;
- author-review and exclusion procedure;
- whether outputs were generated once and stored or generated dynamically at runtime;
- preservation of prompts and outputs in a reproducibility archive.

Without these records, the manuscript must not state that a specific LLM was used.

## Manuscript-wide consistency actions
Remove or rewrite implementation claims in:
- Abstract;
- Section 3.2 and the Figure 2 caption;
- Section 3.2.1;
- mobile-application development description;
- Results statements attributing scenario generation to an LLM;
- Discussion and significance claims;
- limitations and future-work statements that imply an existing LLM component;
- Conclusion.

Do not remove references to external LLM studies from the literature review solely because the proposed framework no longer claims to use an LLM.
